# 浸水ナビ実装 設計書

国土地理院「浸水ナビ」（https://suiboumap.gsi.go.jp/ ）の API を本ビューワへ組み込むための設計。

**状態: 実装済み**（本書の方針どおり実装し、実ブラウザで動作を確認した。実装後に判明した点は各節に追記している）

- 対象 API 仕様書: 「浸水ナビ API 仕様及び使用方法の説明書」3.2 版（令和 5 年 3 月）
- 参考実装: `nobeoka-city`（Next.js + React hooks、延岡市域向け）

---

## 1. 何を作るか

現状のビューワは「洪水浸水想定区域」など**法に基づき指定された静的な区域**を表示している。
浸水ナビは、**どの堤防（想定破堤点）が切れたら、何分後に、どこまで浸水するか**を扱う。
同じ「浸水」でも問いが違うため、別機能として並置する。

|              | ハザードマップ                 | 浸水ナビ                                     |
| ------------ | ------------------------------ | -------------------------------------------- |
| データの性質 | 法指定・公表済みの区域（静的） | 破堤点別のシミュレーション結果（時系列）     |
| 表示単位     | 災害種別ごとの 1 枚            | 破堤点 × 経過時間の組み合わせ                |
| 操作         | トグルで重ねる                 | 破堤点を選ぶ → 時間を動かす                  |
| クリック     | その地点の想定浸水深           | その破堤点が切れた場合の浸水深・浸水開始時間 |

### スコープ

実装する:

- 地図クリックによる想定破堤点の検索と表示（`GetBreakPoint`）
- 破堤点の選択と、経過時間スライダーによる時系列タイルの表示・アニメーション再生
- 最大浸水域タイル（浸水ランク／赤一色）
- 検索可能範囲タイル（rangelayer）
- 破堤点選択後の地図クリックで、経過時間浸水深・最大浸水深・浸水開始時間を表示

実装しない（今回は見送り）:

- ハイドログラフ（`GetHydrograph`）のグラフ描画
- 河川別最大浸水深／最速到達時間／最大継続時間
- 3 時間以内に浸水深 50cm になる破堤点の抽出

## 2. API 仕様の要点

すべて GET。ベース URL は `https://suiboumap.gsi.go.jp/shinsuimap/`。
**`Access-Control-Allow-Origin: *` が返るため、静的サイト（GitHub Pages）から直接呼べる**ことを実測で確認済み。

### 2.1 使用する JSON API

| 用途             | エンドポイント                 | 主なパラメータ                        |
| ---------------- | ------------------------------ | ------------------------------------- |
| 破堤点の検索     | `Api/Public/GetBreakPoint`     | `lon`, `lat`（任意で `returnparams`） |
| 経過時間の浸水深 | `Api/Public/GetMaxDepthByTime` | `lon`, `lat`, `bptime`, `bpid`        |
| 最大浸水深       | `Api/Public/GetMaxDepth`       | `lon`, `lat`, `bpid`                  |
| 浸水開始時間     | `Api/Public/GetFloodStartTime` | `lon`, `lat`, `bpid`                  |

`GetBreakPoint` の戻り値（1 件ぶん、実際のレスポンスより抜粋）:

```json
{
  "ID": "afb08944-d386-4018-97df-9b6ae93c0e1e",
  "BPName": "BP263",
  "BPLocation": "荒川右岸 10.25k",
  "BPLat": 35.741771,
  "BPLon": 139.819219,
  "CSVScale": 0,
  "EntryRiverName": "荒川",
  "RiverCode": "8303040001",
  "SubRiverCode": "_",
  "OfficeCode": "21281",
  "BPTime": [10, 20, 30, ..., 1440, 2160, 2880, 3600],
  "isDepthMax": true,
  "isStartMax": false,
  "isDurationMax": false
}
```

押さえるべき点:

- **`BPTime` は破堤点ごとに異なる**。この配列に無い経過時間のタイルは存在しない
- `isDepthMax` / `isStartMax` / `isDurationMax` は「その地点に最大浸水深／最速の浸水開始／最長の浸水継続をもたらす破堤点」のフラグ
- `CSVScale` は降雨規模コード（`0`=想定最大規模, `1`=計画規模, `-1`=降雨規模未区分）
- 検索結果が無い場合は `[]` を返す（エラーではない）

### 2.2 使用するタイル API

地理院タイル仕様（`{z}/{x}/{y}.png`）。**データが無い場合は 404**（＝正常。エラー扱いしない）。

```
時系列          Tile/{事務所}/{規模}/{拡張河川コード}/{破堤点名}/{破堤点名}_{経過時間5桁}m/{z}/{x}/{y}.png
最大(ランク別)   Tile/{事務所}/{規模}/{拡張河川コード}/{破堤点名}/{破堤点名}_MAX/overlayer/{z}/{x}/{y}.png
最大(赤一色)     Tile/{事務所}/{規模}/{拡張河川コード}/{破堤点名}/{破堤点名}_MAX/baselayer/{z}/{x}/{y}.png
検索可能範囲     Tile/rangelayer/{規模}/{z}/{x}/{y}.png
```

URL 組み立てのルール（実装時に間違えやすい）:

- **拡張河川コード** = `RiverCode` + `SubRiverCode`。ただし `SubRiverCode` が `"_"` のときは `RiverCode` のみ
- **規模** は `CSVScale` を文字列へ変換: `0`→`L2`, `1`→`L1`, `-1`→`L1b`
- **経過時間** は 5 桁ゼロ埋め（`60` → `00060`）し、`{破堤点名}_00060m` の形にする

実測（荒川・BP272, OfficeCode=21281, RiverCode=8303040001）:

```
Tile/21281/L2/8303040001/BP272/BP272_00060m/14/14554/6447.png   → 200
Tile/21281/L2/8303040001/BP272/BP272_MAX/overlayer/14/14554/6447.png → 200
Tile/rangelayer/L2/12/3639/1612.png                              → 200
```

**タイルの最大ズーム（native zoom）は 16**。z17 は 404 になる（浸水ナビ本体の
`map.leaflet.js` でも `tileNativeZoom = 16`）。ラスタソースに `maxzoom: 16` を指定し、
それ以上は拡大表示にする。

### 2.3 ハザードマップポータルのタイルとの違い

同じ「浸水」を扱うが、**タイルの切り方が根本的に違う**。実装方針に直結するため整理する。

|            | ハザードマップポータル（disaportaldata）              | 浸水ナビ                                               |
| ---------- | ----------------------------------------------------- | ------------------------------------------------------ |
| URL        | `raster/01_flood_l2_shinsuishin_data/{z}/{x}/{y}.png` | `Tile/{事務所}/{規模}/{拡張河川コード}/{破堤点名}/…`   |
| 単位       | **全国 1 枚のモザイク**（全河川・全管理者を合成済み） | **想定破堤点ごと**（＝氾濫の原因ごと）                 |
| 時間       | 無し（最終的な浸水想定のみ）                          | 有り（破堤からの経過時間 10 分〜3600 分）              |
| 河川の区別 | できない（どの川の氾濫かは分からない）                | 破堤点が河川に紐づく（`EntryRiverName` / `RiverCode`） |
| 前提       | 「この区域は浸水想定区域に指定されている」            | 「この堤防が切れたら、何分後にここまで来る」           |
| 最大ズーム | —                                                     | 16                                                     |

**河川単位で束ねたタイルは存在しない。** 実測で確認済み:

```
Tile/21281/L2/8303040001/MAX/overlayer/…            → 404
Tile/21281/L2/8303040001/_MAX/overlayer/…           → 404
Tile/21281/L2/8303040001/8303040001_MAX/overlayer/… → 404
```

パス中の拡張河川コードは階層としての意味しか持たず、**葉は必ずシミュレーション単位
（破堤点名 `BPName` ／ 台風コース名 `TCName` ／ 津波波源名 `TSName`）**になる。
河川全体の浸水域が見たい場合は、その河川の破堤点を 1 つずつ重ねる必要がある。

なお `TCName`（高潮）・`TSName`（津波）のタイルは構造こそ同じだが、実データが
登録されていない（12 章の 5 を参照）。**実質的に浸水ナビは洪水（河川の破堤）専用**である。

唯一の広域集約タイルは `rangelayer`（検索可能範囲）だが、これは「どこにデータがあるか」
を示すだけで浸水深は持たない。

→ **結論**: 浸水ナビはハザードマップポータルの代替ではなく、**補完**である。
「指定区域として浸水想定区域に入っているか」はハザードマップポータルのタイルで、
「どの堤防が切れると、いつ、どれだけ浸水するか」は浸水ナビで見る。
本ビューワで両者を分けて扱う理由もここにある。

### 2.4 仕様書に無いタイル（浸水ナビ本体が使用）

浸水ナビ本体（`Scripts/shared/mapcommon.js` の `createTileUrl`）は、API 仕様書に記載の無い
タイルも使っている。実測でも 200 が返ることを確認した。

```
浸水開始時間      Tile/{事務所}/{規模}/{拡張河川コード}/{破堤点名}/TIME/StartTime/{z}/{x}/{y}.png
浸水継続時間      Tile/{事務所}/{規模}/{拡張河川コード}/{破堤点名}/TIME/Duration50/{z}/{x}/{y}.png
```

`Duration50` は「浸水深 50cm 以上が継続する時間」。`Duration70` はコード上コメントアウトされている。
対応する凡例色も本体の HTML に定義がある（`floodArriveColors` / `floodContinueColors`）。

これらは**公開 API として保証されていない**ため、今回の実装では採用しない。
採用する場合は、予告なく変わりうる前提で扱う。

### 2.5 利用上の制約

仕様書の「API 利用上の注意」より:

- **分間リクエスト数 30 以下程度（2 秒に 1 回）**。過負荷と判断されたアクセスは予告なく遮断される
- 国土交通省ホームページのリンク・著作権・免責事項が適用される
- 本 API を用いた行為について国土地理院は責任を負わない

→ 設計上、**JSON API 呼び出しは必ずスロットル（最短 2 秒間隔）を通す**。タイルは MapLibre が必要ぶんだけ取得するため個別制御はしないが、アニメーションの更新間隔は 2 秒とする。

## 3. レイヤー構造の分離

### 3.1 方針

ハザードマップ群と浸水ナビ群を**別グループとして管理**する。
現在は `hazardBeforeId()` / `overlayFloorId()` という個別関数で挿入位置を決めているが、グループが増えると破綻するため、
**スロット順を 1 箇所に定義し、`beforeId` を機械的に求める方式**へ改める。

```
背景スタイル（淡色 / 写真）
  ├─ 陰影起伏図
  ├─ 背景の地物（水域・道路・建物 …）
  │
  ├─ [slot] suibou-range      検索可能範囲（rangelayer）
  ├─ [slot] suibou-max        最大浸水域（赤一色 → 浸水ランク）
  ├─ [slot] hazard            ハザードマップ 15 種（config の並び順）
  ├─ [slot] suibou-timeseries 時系列タイル（選択中の破堤点）
  ├─ [slot] population        100m メッシュ人口
  ├─ [slot] plateau           PLATEAU 3D建物
  │
  ├─ 背景スタイルの地名ラベル（最初の symbol レイヤー以降）
  │
  ├─ [slot] suibou-points     破堤点（circle）＋ 選択ハイライト
  └─ [slot] pins              指定緊急避難場所・自然災害伝承碑
```

この順にした理由:

- **検索可能範囲は最下**: 「どこに浸水ナビのデータがあるか」を示す下地であり、他を隠してはいけない
- **最大浸水域はハザードの下**: 最終的な浸水範囲の参照用。ハザードと重ねたとき、法指定区域の方を手前に見せる
- **時系列タイルはハザードの上**: シミュレーション中はこれが主役
- **人口・3D建物はさらに上**: 「浸水域に誰が住んでいるか」「建物の高さと浸水深の比較」という重ね方をするため
- **破堤点はラベルより上**: クリック対象なので隠れてはいけない
- **ピンが最前面**: 避難先は常に見えるべき

### 3.2 実装（`src/map/layer-order.ts`）

```ts
/** 下から上への描画順。各スロットに属するレイヤーIDを返す */
export const LAYER_SLOTS = [
  'suibou-range',
  'suibou-max',
  'hazard',
  'suibou-timeseries',
  'population',
  'plateau',
  'labels', // 背景スタイル側の最初の symbol レイヤー
  'suibou-points',
  'pins',
] as const;

/** slot に属するレイヤーを挿入するときの beforeId */
export function beforeIdFor(map, slot, layerIdsInSlot): string | undefined;
```

`beforeIdFor` は「自分より上のスロットで、既に地図に載っている最初のレイヤーID」を返す。
同一スロット内の順序（ハザード 15 種、時系列の複数枚など）は、各スロットが自前で解決する。
これにより、**どのグループを先に載せても最終的な重ね順が同じ**になり、背景/テーマ切替後の再構築でも順序が保たれる。

### 3.3 既存コードへの影響

- `main.ts` の `labelBeforeId()` / `overlayFloorId()` / `hazardBeforeId()` は `layer-order.ts` に集約して置き換え
- `buildLayers()` は「ハザード群を貼る」「浸水ナビ群を貼る」「オーバーレイ群を貼る」の 3 呼び出しに整理
- 背景/テーマ切替（`setStyle diff:false`）後の再構築、WebGL コンテキスト復帰後の再構築は現行と同じ経路を通す

## 4. 状態設計

浸水ナビの状態はハザードとは独立させ、`PanelState` に並置する。

```ts
export interface SuibouState {
  /** 浸水シミュレーションモードの ON/OFF */
  active: boolean;
  /** 直近の検索でヒットした破堤点（クリック地点を浸水させるもの） */
  breakPoints: BreakPoint[];
  /** 選択中の破堤点 */
  selected: BreakPoint | null;
  /** 選択中の破堤点の BPTime 配列に対するインデックス */
  timeIndex: number;
  /** アニメーション再生中か */
  playing: boolean;
  /** 重ねる浸水ナビタイル */
  layers: {
    timeseries: boolean; // 既定 ON
    maxRank: boolean; // 最大浸水域（浸水ランク）
    maxRed: boolean; // 最大浸水域（赤一色）
    range: boolean; // 検索可能範囲
  };
  /** タイルの不透明度（ハザードとは別に持つ） */
  opacity: number;
}
```

設計上のポイント:

- **経過時間は「分」ではなくインデックスで持つ**。参考実装は 10 分刻みの自由な値を取れるスライダーだったが、
  `BPTime` に無い値ではタイルが存在せず「動かしても何も変わらない」状態が起きる。
  インデックスで持てば、**スライダーの全位置で必ずタイルが存在する**
- 破堤点を切り替えたら `timeIndex` は 0 に戻す（`BPTime` の中身が破堤点ごとに違うため）

## 5. UI 設計

左サイドパネルに「浸水シミュレーション」セクションを新設する（ハザードマップの下、重ねる情報の上）。

```
ハザードマップ（重ねられます）        [全OFF]
  ⦿ 洪水浸水想定区域（想定最大規模） ⓘ
      [───────●──] 80%
      ■ 20.0m以上 …

浸水シミュレーション（浸水ナビ）  ← 新設
  ⦿ 破堤点を探す                   ⓘ
      地図をクリックすると、その地点を
      浸水させる想定破堤点を表示します
      [ 検索可能範囲を表示 ]
  ── 選択中 ──────────────
  荒川 BP272（荒川左岸 12.0k）
  ⚠ この地点に最大の浸水をもたらす破堤点
      経過時間  [──●─────] 180分
      [▶ 再生] [■ 停止]
      ⦿ 最大浸水域（浸水ランク）    ⓘ
      ⦿ 最大浸水域（赤一色）        ⓘ
      [───────●──] 不透明度 80%
      ■ 凡例 …

重ねる情報
視点 [2D | 3D]
```

- 破堤点未選択のときは「選択中」以下を隠す
- 経過時間スライダーの下に、実際の値（`180分` / `1日6時間` のような可読表記）を出す
- 再生中はスライダーを無効化（参考実装と同じ）。末尾に達したら自動停止する
  （参考実装は上限なく加算し続けて範囲外へ行く作りだったので、ここは変える）
- 破堤点が見つからなかった場合は「この地点を浸水させる想定破堤点は登録されていません」を表示

### 地図クリックの優先順位

クリック処理が競合するため、単一のハンドラで次の優先順に捌く。

1. 避難場所・伝承碑・人口メッシュのフィーチャ上 → 既存のポップアップ
2. 破堤点マーカー上 → その破堤点を選択
3. 浸水ナビ ON かつ破堤点が未選択 → `GetBreakPoint` で破堤点を検索
4. 浸水ナビ ON かつ破堤点が選択済み → 浸水深ポップアップ（後述）
5. それ以外 → 既存のハザード浸水深ポップアップ

「破堤点を選び直したい」場合のために、パネルに「破堤点を再検索」ボタンを置く。

## 6. ポップアップ

破堤点選択後に地図をクリックしたときの表示（API 3 本を並行呼び出し）。

```
BP272 荒川左岸 12.0k が破堤した場合
────────────────────────
経過180分時点の浸水深      4.02 m
最大浸水深                5.31 m
浸水開始まで              25 分
────────────────────────
🌎Google Maps
```

- `GetMaxDepthByTime` の `bptime` には**現在の経過時間そのもの**を渡す（`BPTime` の要素なので丸め不要）
- いずれかが結果なし（`[]`）の場合はその行だけ「該当なし」にする
- 3 本同時に呼ぶためスロットルの間隔を消費する。連打対策として、進行中のリクエストは `AbortController` で中断する

## 9. 動作確認の方針

Playwright（Chromium）で dev サーバーに対して実施する。確認項目:

- 破堤点検索 → 表示件数、`isDepthMax` の強調
- 破堤点選択 → 時系列レイヤーが `suibou-timeseries` スロットに入り、重ね順が設計どおりか
- スライダー操作 → タイル URL の経過時間が変わり、404 が出ないこと
- 再生 → 2 秒間隔で進み、末尾で停止すること
- 浸水深ポップアップ → 3 値が出ること
- 背景・テーマ切替後に、選択状態・経過時間・レイヤー構成が復元されること
- ハザードと同時表示したときの重ね順

**API 負荷に注意**し、テストは連打せず、必要最小限の回数に留める。

## 9.1 実装後に分かったこと

- **`GetBreakPoint` は遅いことがある。** 荒川下流のように多数の河川・破堤点が重なる地点では
  **460 件**が返り、応答まで 10 秒前後かかった。検索中であることを明示する状態表示は必須。
- **破堤点が数百件返ると、地図上から目的の点を選ぶのが難しい。** そのため
  「最大浸水の破堤点を選ぶ」ショートカットボタンを追加した（`isDepthMax` の破堤点を 1 タップで選択）。
- **同一地点でも降雨規模が混在する。** 実測では想定最大規模（L2）と計画規模（L1）の破堤点が
  同じ検索結果に含まれた。選択中の破堤点には規模ラベルを表示している。
- 破堤点が密集するズームでは円が重なるため、クリックで意図しない破堤点が選ばれることがある。
  選択中の破堤点はパネルに名称・位置・規模を出しているので、そこで確認できる。

## 12. 未決事項・確認が必要なもの

1. ~~**浸水ランクの凡例色**~~ → **解決済み**
   浸水ナビの凡例画像（`shinsuimap/Images/legend.png`）を確認したところ、浸水ランクの区分は
   `0.5m未満 / 0.5〜3.0 / 3.0〜5.0 / 5.0〜10.0 / 10.0〜20.0 / 20.0m以上` で、
   **ハザードマップの洪水浸水想定区域と同じ配色**だった。
   `config/hazard-layers.ts` の `SWATCHES_SHINSUISHIN` をそのまま流用する。
   （凡例には「浸水ランク（旧式）」＝ 4 区分の系統もあるため、古いデータでは色が異なりうる）
2. **降雨規模（`CSVScale`）が混在する場合の扱い**
   同じ地点の破堤点でも `0`（想定最大規模）と `1`（計画規模）が混在しうる（実測でも確認）。
   破堤点リストに規模バッジを出すか、規模で絞り込むかを決める。
3. ~~**時系列レイヤーのキャッシュ方針**~~ → **決定済み**
   参考実装は読み込んだ時刻ぶんのレイヤーを `visibility: none` で残すが、破堤点あたり 30 枚近くに
   なりモバイルのメモリを圧迫するため、**表示中の 1 枚だけを残して破棄する**方式にした。
   再生時の滑らかさより、地形＋3D建物と併用したときの安定性を優先している。
4. **モバイルでのアニメーション**
   タイルの読み込みが 2 秒に間に合わない回線では飛び飛びになる。再生間隔を可変にするか要検討。
5. ~~**高潮（台風コース）・津波（津波波源）への拡張**~~ → **見送り確定（データが無い）**

   浸水ナビ本体には「津波」「高潮」タブ（海岸選択 → 海岸名 → 規模指定）があり、内部APIと
   タイル構造も用意されている（タイルの葉が `BPName` の代わりに `TSName` / `TCName` になるだけ）。

   ```
   /ShinsuiMap/api/search/SearchTsunamiSourceByPosition   座標からの津波波源検索
   /ShinsuiMap/api/search/SearchTyphoonCourseByPosition   座標からの台風コース検索
   ```

   ただし調査の結果、**拡張しても表示できるデータが無い**ことが分かった。

   - **公開 API 仕様書（3.2版）に載っているのは破堤点（洪水）のみ。** 津波・高潮の
     エンドポイントは 1 つも無く、検索系は本体内部 API に依存する
   - **海岸リストの実データが「テスト海岸」1 件しか無い。** `Data/pref_coast_tsunami.json`
     と `Data/pref_coast_surge.json` を取得したところ、いずれも中身は次の 1 件だけだった

     ```json
     [
       {
         "pname": "関東地方整備局",
         "oname": "江戸川河川事務所",
         "ccode": "1234T001",
         "cname": "テスト海岸",
         "sname": "想定最大規模"
       }
     ]
     ```

     コード（`1234T001` = 津波 / `1234S001` = 高潮）と名称から、枠組みだけ実装され
     実データの登録が進んでいない状態と読める

   → 津波・高潮は、本ビューワでは**ハザードマップポータルの津波浸水想定・高潮浸水想定区域**
   （法に基づく静的な指定区域）で引き続き対応する。浸水ナビ側にデータが登録された時点で、
   本項を再検討する。

## 付録: 開発環境のメモ

- `suiboumap.gsi.go.jp` は TLS の legacy renegotiation を要求するため、環境によっては `curl` が
  `unsafe legacy renegotiation disabled` で失敗する。動作確認で curl を使う場合は OpenSSL の
  `Options = UnsafeLegacyRenegotiation` を有効にした設定を `OPENSSL_CONF` で渡す。
  **ブラウザからのアクセスには影響しない。**
- WSL 上で `/mnt/c` 配下の dev サーバーはファイル監視が効かない。編集のたびに再起動が必要。
