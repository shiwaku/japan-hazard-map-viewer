# 浸水ナビの対象河川数と、重ねるハザードマップとの差異

浸水ナビ（想定破堤点シミュレーション）が全国のどの河川をカバーしているのか、
重ねるハザードマップに掲載されている洪水浸水想定区域（想定最大規模）と比べてどう違うのかを整理する。

- 調査日: 2026-08-08
- 対象: 洪水（河川の想定破堤）。浸水ナビは実質的に洪水専用（[設計書](suibou-navi-design.md)の 12 章 5 を参照）

---

## 1. 結論

|                                          | 浸水ナビ  | 重ねるハザードマップ（L2）    |
| ---------------------------------------- | --------- | ----------------------------- |
| 国管理河川                               | **434**   | **442**（河川名の異なり 430） |
| 都道府県管理河川                         | **3,770** | **1,695**（同 1,481）         |
| その他河川（都道府県・市町村が独自作成） | —         | **8,800**（同 6,478）         |
| 法に基づく指定（国＋都道府県）の計       | **4,204** | **2,137**                     |

- **国管理はほぼ一致**（434 / 442）。浸水ナビは国管理河川をほぼ網羅している
- **都道府県管理は浸水ナビの方が 2 倍以上多い**（3,770 / 1,695）。
  浸水ナビにあってポータルの法指定一覧に無い河川の多くは、ポータル側では
  「その他河川（水防法の指定ではなく、都道府県・市町村が独自に作成・公表したもの）」に含まれる
- 逆に、**区域図は公表されているが浸水ナビに破堤点シミュレーションが無い河川**も 224 件ある（河川名ベース）

つまり両者は母集団が異なる。**「指定区域として載っているか」と「破堤シミュレーションがあるか」は別**であり、
どちらか一方だけでは全体像にならない。本ビューワで両方を並べている理由でもある。

## 2. 浸水ナビ側の内訳（4,204 河川）

### 2.1 数え方の注意

浸水ナビの河川は `rcode`（河川コード）と `srcode`（河川コード枝番）の組で識別する。

- `rcode` + `srcode` でユニーク: **4,204**
- `rcode` のみでユニーク: 4,004
- 河川名の異なり: 3,559
- レコード数（河川 × 降雨規模）: 7,810

同じコードでも名称の表記が異なるレコードがあるため、名称を含めて数えると 4,268 になる。
**本書では 4,204（コード＋枝番）を採用する。**

| 国管理（地方整備局・北海道開発局） | 434    |
| 都道府県管理（45 都道府県）        | 3,770  |

国管理の内訳（事務所は全 148）:

### 2.3 降雨規模別

同じ河川が複数の規模を持つため、合計は河川数と一致しない。

| 規模（`scode`）              | 河川数 |
| ---------------------------- | ------ |
| 想定最大規模 L2（`0`）       | 4,170  |
| 計画規模 L1（`1`）           | 3,066  |
| 計画規模・旧凡例 L1b（`-1`） | 91     |

## 3. 重ねるハザードマップ側の数値

[オープンデータ配信ページ](https://disaportal.gsi.go.jp/hazardmap/copyright/opendata.html)から、
洪水浸水想定区域（想定最大規模）の掲載状況一覧 CSV を取得して数えた。

| 区分             | 行数  | 河川名の異なり | 内容                                       |
| ---------------- | ----- | -------------- | ------------------------------------------ |
| 国管理河川       | 442   | 430            | 水防法に基づく指定                         |
| 都道府県管理河川 | 1,695 | 1,481          | 水防法に基づく指定                         |
| その他河川       | 8,800 | 6,478          | 都道府県・市町村が独自に作成・公表したもの |

「その他河川」の一覧ページには「現在整備中のため、一部の情報が空欄の河川がございます」との注記がある。

## 4. 河川名での突き合わせ（参考値）

ポータルの CSV に河川コードが無いため、**河川名でしか照合できない**。以下は参考値。

|                                   | 件数                                |
| --------------------------------- | ----------------------------------- |
| 浸水ナビ ∩ 法指定（国＋県）       | 1,454                               |
| 浸水ナビ ∩ 全体（その他河川込み） | 2,994                               |
| 浸水ナビにあり、法指定に無い      | 2,105                               |
| 　うち「その他河川」に載る        | 1,540                               |
| 　どこにも載らない                | 565                                 |
| 法指定にあり、浸水ナビに無い      | 224                                 |
| 国管理どうしの一致                | 396 /（浸水ナビ 423・ポータル 430） |

「どこにも載らない 565」の多くは表記の差と見られる。浸水ナビ側には
`一ツ瀬川（上流）` `トンボ川（拡散型）` `一庫・大路次川（上流）` のような、
**シミュレーション単位で付けられた独自名称**があるため、単純な文字列一致では拾えない。

## 5. 取得方法（再現手順）

### 浸水ナビの河川一覧

**公開 API 仕様書には河川一覧を取得する手段が無い**（公開 API は地点指定の `GetBreakPoint` など）。
浸水ナビ本体が河川選択メニューに使っている内部 API から取得した。

```
https://suiboumap.gsi.go.jp/ShinsuiMap/api/manage/GetRiverSelectMenu
```

返却は 7,810 レコードの JSON。1 レコードは河川 × 降雨規模で、次の形。

```json
{
  "pname": "北海道開発局",
  "oid": "20757",
  "oname": "札幌開発建設部",
  "rcode": "8101030001",
  "srcode": "_",
  "rname": "石狩川",
  "scode": "0",
  "sname": "想定最大規模",
  "csvid": "00221d95-d010-4d82-81de-cb89998496c9",
  "GroupCode": "81"
}
```

> **注意**: これは公開 API として保証されていない内部エンドポイントである。
> 全国の網羅性を把握する目的で 1 回だけ取得した。**アプリから継続的に叩く用途には使わない。**

### 重ねるハザードマップの掲載状況一覧

```
https://disaportal.gsi.go.jp/hazardmapportal/hazardmap/copyright/csv/kasen_kuni_L2.csv
https://disaportal.gsi.go.jp/hazardmapportal/hazardmap/copyright/csv/kasen_pref_L2.csv
https://disaportal.gsi.go.jp/hazardmapportal/hazardmap/copyright/csv/kasen_sonota_L2.csv
```

列は `通し番号, 通し番号, 都道府県名(事務所名), 水系名, 河川名, …, 更新日, 出典`。文字コードは CP932。

### 環境上の注意

`suiboumap.gsi.go.jp` は TLS の legacy renegotiation を要求するため、環境によっては `curl` が
`unsafe legacy renegotiation disabled` で失敗する。OpenSSL の `Options = UnsafeLegacyRenegotiation`
を有効にした設定を `OPENSSL_CONF` で渡すと取得できる。**ブラウザからのアクセスには影響しない。**
